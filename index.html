3. 五个方案

方案一 外流（已有做法）：C++ 因子 + DSL 拼装 + F1 公式

flowchart LR A["5000行 finalscore"] --> B["拆成多个 C++ 因子
admit/compute，可嵌套 factor udf"] --> C["DSL 小算子拼大算子"] --> D["F1 最终公式（纯math）"]

加一个因子要改：C++ 因子类 + 注册 + DSL 接线 + 公式（3~4 处，需上线）。

✅ 分而治之、表达能力等价原 C++、阶段明确（因子C++ + 公式math）、成功拆文件。
❌ 基本没配置化；代码分散难找；因子能否复用没人知道；加一个乘法代码量大。
证据：common_se_defs.h:145 FINISH_ADMIT、:164 FINISH_COMPUTE（会话核对）

方案二 C++ 前处理 + F1 + C++ 后处理

flowchart LR A["C++ 前处理
字典/名单/有序参数"] --> B["F1 主公式"] --> C["C++ 中间：PC置换/AUC"] --> D["F1 依据摘要调分"] --> E["C++ 保护/排序/写回"] --> F["两轮间 top61 → 第二轮"]

改公式：若在 F1 段只改配置；若落在 C++ 段需改 C++ 上线。

✅ 折衷可行，类似外流 finaladjust bonus 阶段；不改公共 F1 库。
❌ 因子计算阶段也有变量和公式，口子一开，大量公式最终仍留在 C++；须按依赖切段（PC 在主公式后、AUC 居中、top61 在两轮间）；数值问题仍在。

方案三 KaiFG + F1

flowchart LR A["KaiFG Python 程序
（编译成 .so）"] --> C["DSL 编排"] B["F1 公式配置"] --> C --> D["Dragon 写回"]

改复杂逻辑：改 Python → 重编 .so → 上线；改简单公式：F1 配置。

✅ 表达力等价 C++（v3 支持 lambda/sort(key)/NumPy）。
❌ 不是配置化，逻辑上与方案二相同，只是 C++ 换成 Python；公式未统一收口；升级仍需上线。
证据：KaiFG 进程级单例 + call_once 编译加载 kaifg_client.cc:393-411，无同进程热更；整包编译会影响其他节点。

方案四 纯 F1 + 注册 UDF（用户倾向）

flowchart LR I["common（含AB）+ item 属性"] --> F["F1 公式（多份配置，唯一配置系统）"] U["业务 UDF（C++，编译链接时注册）
PC_REASSIGN / AUC / top61 ..."] --> F F --> O["配置声明的输出 → 写回"]

改因子/公式：只改 F1 配置；中间因子变量支持参数注入。仅新增一种稳定算法时才写 UDF 上线（低频）。

✅ 公式只关心 common/item 数值运算；UDF 可操作输入 common/item 属性，能做的计算与 KaiFG/C++ 无差异；特殊逻辑迭代少（git：PC/AUC 近90天未改、top61 自2025-11未改）；统一收口。
❌ F1 注册 UDF 目前不是插接式（集中注册 f1_udf_collection.h:558），需向 F1 团队提需求；UDF 拿到的是 F1Context（值导入的数据），非 DragonContext；多输出/跨 item 状态需额外设计（LTR 2026-10-09 刚改，状态规则不宜固化 C++）；float32 逐位一致未解决。

方案五 参考 Aether：纯 Python 即配置，编译出 KaiFG + DSL + F1

flowchart LR P["用户 Python 文件
只声明 输入common/item、AB、中间变量、输出"] --> C["编译器"] --> K["KaiFG"] & D["DSL"] & F["F1 公式"] --> R["Parent 上线"]

✅ 解决方案三“用户感知到不需要的技术细节”；Python 文件即配置。
❌ 仍需编译上线，Parent 上线慢，非快速迭代；公式冷热未分离；需自建编译器。

6. 风险与待决问题

  1. F1 注册注入需求：实例级工厂、配置重载保留注册（formula1.cc:34）、重名报错、是否提供求值时上下文绑定。
  2. 多输出/状态：UDF 返回 double/缓存整列；分数+order+状态的绑定；LTR carry 用通用执行器还是前置参数序列。
  3. float32 逐位一致未验证：原语单测已见 float 转换、int 除法、-0 符号差异；近分时排序可翻转。
  4. AB 整组版本：入口选配置集 + 公式内 AB 条件；请求固定版本、旧版本生命周期。
  5. EMER 是否改异步；后续策略/GroupPK 是否接入同一引擎；epsilon 比较器非严格弱序。
